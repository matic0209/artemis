# 架构设计

## 模块划分
- **artemis-core**：框架运行时，包含事件总线、策略管理、执行器桥接、度量指标
- **core/clients**：与第三方服务交互的适配层，目前提供 OpenSea V2 客户端
- **strategies**：策略集合，按业务域拆分子 crate
  - `mev-arbitrage`：图论、符号执行、REVM 验证、防御模块
  - `sandwich`：围绕 Sandwich MEV 的监控与对策
  - `uniswap-arb`、`opensea-arb` 等：针对特定协议的套利逻辑
- **bin**：具体可执行程序，如 `artemis` 主节点与 `cli` 辅助工具
- **examples**：演示如何快速扩展 Collector、Strategy 与 Executor

## 运行时流程
```
┌──────────┐   事件   ┌───────────┐   动作   ┌───────────┐
│Collectors├────────►│ Strategies├────────►│ Executors │
└──────────┘         └───────────┘         └───────────┘
       ▲                   │                        │
       │                   ▼                        ▼
   外部数据源         状态/缓存           链上交易或其他输出
```

1. **Collector 注册**：通过 `CollectorMap` 将数据源事件绑定到统一枚举类型
2. **Strategy 添加**：策略实现 `Strategy<Event, Action>`，可维护内部状态、缓存
3. **Executor 挂载**：使用 `ExecutorMap` 将策略 Action 定向到具体执行器
4. **Engine 调度**：基于异步任务循环驱动生产消费，并提供 backpressure 控制

## 关键技术点
- **异步与并发**：Tokio runtime + `tracing` 日志，辅以自适应线程池、零拷贝缓冲等优化
- **符号执行管线**：`strategies/mev-arbitrage/symbolic-execution` 使用 Z3 探索执行路径，生成验证条件
- **图论模块**：利用 `petgraph` 构建加权有向图，识别负权回路以定位套利机会
- **执行验证**：REVM 模块对候选交易进行本地模拟，避免因状态差异导致的失败
- **度量与监控**：`metrics_exporter_prometheus` 暴露指标，结合 `tracing` 形成完整观测

## 配置与扩展
- 新增 Collector：实现 `Collector` trait，并在 `Engine` 中注册映射
- 新增 Strategy：在对应 crate 内创建模块，复用 `artemis-core` 提供的缓存、事件过滤工具
- 新增 Executor：实现签名与发送逻辑，可根据 Action 类型自定义多路分发
- Feature Flag：如 `rbuilder-integration` 用于启用额外执行路径

## 依赖关系概览
- Ethereum 相关：Alloy 系列库、mev-share、opensea-stream
- 分析工具：Z3、petgraph、rayon 等
- 并发工具：tokio、crossbeam、parking_lot、dashmap

## 潜在改进点
- 部分策略 crate 仍为占位实现（存在大量未使用字段），后续可按需精简
- 建议将共享的工具模块（如监控、缓存）提取至独立 crate，减少重复代码
- 考虑引入配置中心（YAML/TOML）统一管理 Collector/Strategy/Executor 配置

更全面的重构建议见 `docs/重构评估.md`。
