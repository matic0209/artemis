# 开发工作流

## 代码规范
- 统一使用 `rustfmt` 与 `clippy`：`cargo fmt --all`、`cargo clippy --workspace --all-targets`
- 保持模块分层：Collector / Strategy / Executor 不直接耦合
- 使用 `tracing` 日志宏记录关键路径，避免 `println!`
- 针对跨线程共享结构优先选择 `Arc` + `RwLock` 或 channel，而非全局静态变量

## 测试策略
- **单元测试**：在各子 crate 内补充 `#[cfg(test)]` 模块
- **集成测试**：`tests/` 目录可以模拟事件流，验证策略输出
- **模拟执行**：对关键策略调用 REVM 验证，确保在最新状态下仍可执行
- **基准测试**：利用 `--benchmark` 模式衡量吞吐与延迟

## 本地调试
```bash
# 观察事件流
tRUST_LOG=info cargo run -p artemis -- --benchmark

# 仅运行特定示例
cargo run -p quick-start --example basic

# 启动 Prometheus 指标端点
curl http://127.0.0.1:9000/metrics
```

## CI/CD 建议
1. 构建阶段执行 `cargo fmt`, `cargo clippy`, `cargo test`
2. 使用 `cargo deny` 或类似工具审计依赖安全性
3. 发布前执行 `cargo audit` 与针对核心策略的回归测试

## 发布与部署
- 将运行所需的 RPC、API Key、私钥放入安全的配置管理系统
- 建议依赖 Flashbots / MEV-Share 等可信执行通道，降低抢跑风险
- 通过容器化（Dockerfile 已提供基础镜像）部署，并结合 Prometheus/Grafana 监控
